Redis grouped-dispatch measurements (perf round two, work area F). See docs/reports/fragments/redis-f-grouped.md.
Run `npm ci` here once, build tests/Runwick.Workloads in Release, then: `pairs.sh <enq16|enq64|steady500|delayed100|drain> <rounds> [off on on4 on8 on16 bullmq]`. Each round holds /tmp/runwick-bench.lock and alternates arm order; results land in results/<workload>[$RESULT_TAG]/.
Script cost (docs/reports/fragments/redis-script-cost.md): slowdrain.sh runs one drain with SLOWLOG at threshold 0 and prints Redis time per operation (slowparse.py); mondrain.sh runs a small drain under MONITOR and counts the Redis commands each script issues (monparse.py); profile_worker.py --combined also times finish_and_claim and WRAPS=enc,sorted,... times helpers; diffcheck.py also compares reply text and covers FinishAndClaim; pairs-combined.sh arms old/oldbuf run the build in BASE_BIN; summarize_drain.py prints jobs/s, script time and CPU per job per arm.
profile.py times the phases inside the real dispatch scripts against a disposable AOF-always Redis; rawthroughput.py compares single and grouped scripts without the .NET client.
Stored bytes (docs/reports/fragments/redis-store-less.md): writes.py runs claim, FinishMany, Finish and FinishAndClaim against a Redis whose AOF directory is mounted on the host (--aof DIR/appendonlydir) and prints AOF bytes, write commands and fields per job by key kind; summarize_drain.py also prints AOF bytes per job.
Stored-data design (docs/plans/redis-stored-data-design.md): writes.py also measures a single Dispatch and RenewMany, and --fields breaks hash writes down by field (attempt and generation ids folded); profsum.py summarizes several profile_worker.py runs (one file per Lua variant, rounds headed "== <variant> round <n>") as median in-script µs per job and the fixed part per call; slowdrain.sh and pairs-combined.sh take NAME_PREFIX for their container names, and pairs-combined.sh arm oldbuf32 runs BASE_BIN with buffered finish and 32 slots.
Lean path steps (perf-round-2.md, "Redis: lean-path trims and a Functions library, not merged"): profile_worker.py --lean-marks times the steps of the lean claim and finish paths (frame, candidates, decision, after-image, events, writes) with os.clock marks; diffcheck.py normalizes any UUIDv7 decision time.
