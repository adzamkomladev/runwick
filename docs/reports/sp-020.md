## Where the build differs from or adds to the spec

All of these are written into 16 "Changes" (2026-11-08). In short:

- A resend reuses the NotAfter of the first send. NotAfter is part of the command fingerprint, so this costs one extra read per mutation. A resent trigger also derives its proposed job ID from the command ID.
- Without `CursorKey`, cursors are sealed with ASP.NET Data Protection instead of a derived HMAC key. Core alone uses a random per-process key.
- `Audit.Read`, `Capacity.*`, `Schedules.*`, `Settings.Read` and `Retention.Manage` are application-wide. A queue-scoped grant of one of them throws when the grant is built.
- `limit` above 200 is clamped to 200 rather than rejected. Every list is keyset-paged.
- A filter on a queue the caller cannot see returns an empty page. An expired reveal writes no audit row.
- Named the error codes, bulk item statuses and schedule body fields that the spec left open.
- The §5 limits are defaults of `ManagementOptions` and can be changed.
- MGMT-05 drops the reply with the harness fault point, not the TCP proxy.
