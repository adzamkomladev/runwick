# PF-01: round-trip baseline after M3

Date: 2026-11-01. Branch: PF work branched from main at `6fb54f9` (M3 merged, G-2 workloads and owed cases merged). Host: the shared KVM guest (8 vCPU), **non-reference**. Store: `runwick-pg` (PostgreSQL 18) at 127.0.0.1:55499, through `docker-proxy`.

## 1. What PF-01 adds

- `Runwick.Workloads floor` and the `PhaseTimings` meter, taken from the diagnosis branch (`c4dd6e3`) and merged with the G-2 workload commands. `PhaseTimings` records nothing without a listener.
- Test **PERF-01** (`RoundTripBudgetTests`, Postgres tests, `Category=Contract`, `Item=PF-01`, `Case=PERF-01`). It counts the Npgsql commands each operation sends through the `Npgsql` ActivitySource and asserts the exact count per operation. Each later PF item lowers the numbers in the same commit.

What the counter sees: one Npgsql command is one round trip; a multi-statement command is one batch on the wire. Transaction control is not traced, so COMMIT adds one round trip to each driver-owned operation and the staged paths' `SAVEPOINT` and `RELEASE` add two.

Findings:

- M3 added exactly one round trip per job: Begin's `job_rate_requirements` read, which runs for every authorized Begin, rated or not.
- A rated Begin costs +5 over an unrated one: the concurrency-scope read (skipped when there is no rate scope, since the rate step needs it locked first), the rate-scope lock, the window counts, the `last_decision_at` update and the grant insert. The count is the same for 1 and 8 scopes, because every rate statement is set-based.
- The staged paths carry three protocol round trips beyond the operation body: the read-only check, `SAVEPOINT` and `RELEASE`.
- The fixed frame (timeouts, G1, G2, R1, R3, receipt clock, R4, COMMIT) is 8 of every receipted operation's round trips.

## 3. Floor (isolated calls)

`Runwick.Workloads floor --n 100 --warmup 10`, one call at a time on database `rw_pf_a005`. This is the baseline for PF-02. PF-01 itself only adds the zero-cost meter, so it has no separate before/after run.

Load average 14.7 at start, 11.3 at the end (other sessions on the host). Times in ms.

| Operation | wall p50 | wall p90 | SQL commands | SQL wall sum p50 |
|---|---|---|---|---|
| `SELECT 1` (open + 1 RT) | 4.05 | 28.0 | 1 | 3.95 |
| 1-row INSERT transaction | 14.8 | 135 | 1 | 3.92 |
| Dispatch | 99.3 | 326 | 14 | 77.7 |
| Reserve | 92.8 | 332 | 16 | 75.3 |
| Begin | 88.3 | 359 | 15 | 67.0 |
| Renew | 73.8 | 361 | 8 | 47.2 |
| Finish | 133 | 389 | 15 | 98.1 |

At this load a round trip costs 5–6 ms at p50, about twice the diagnosis's isolated figure (load 3–5). The command counts above are deterministic; the latencies are not, and are useful only next to an interleaved run on the same host.
