# SP-005 acceptance report: PostgreSQL schema, migrator, runner and receipts

Date: 2026-10-30. Tag: `sp-005`.

## Delivered

- `src/Runwick.Postgres/Sql/0001_initial.sql` is the DDL from spec 04 §4, unchanged and embedded as a resource.
- `Migrations/PgMigrator.cs` implements spec 04 §8:
  - A dedicated `Pooling=false` session and the advisory lock `5941776742533524273`, polled for up to 60 s.
  - Preflight checks: server ≥ 16, UTF8 encoding and `standard_conforming_strings`.
  - Per-phase ledger rows with LF-normalized SHA-256 checksums. A checksum mismatch is a hard error.
  - Expand, validate (catalog checks from §8.3) and activate, each in its own transaction with `lock_timeout` 5 s and `statement_timeout` 60 s.
  - The manifest from §8.5. Its digest is computed over `runwick.manifest.v1` with the canonical encoder.
  - The public entry point is `RunwickPostgresMigrations.MigrateAsync` (spec 04 P-18).
- `Store/PgDataSources.cs`: a control data source (6 connections) and a work data source (8 connections), with the call-class gates 4/2 and 4/2/2 and the §9.2 Npgsql settings.
- `Store/PgRunner.cs` is the §6 transaction runner:
  - Gates G1 and G2, receipts R1–R4, and the decision time read from `clock_timestamp()` after locks.
  - Same-identity retry of 40P01, 40001 and 55P03, up to 3 times.
  - SQLSTATE classification per §10. Any failure after COMMIT has been sent is classified as outcome unknown.
  - Fault points from 07 §2.3.
- `Store/PgStore*.cs` implements every operation in 04 §7 and resolves to `IRunwickStore`:
  - Describe and Register*.
  - Dispatch and DispatchMany: sorted key locks, window/active resolution cases a–f, all-or-nothing batches, and the per-ordinal conflict detail.
  - ResolveCommand and ResolveOperation (always roll back).
  - Reserve, including SKIP LOCKED candidates, the capacity check after locks, and fences.
  - Begin: authorize, cancel-before-start and budget-exhausted.
  - Renew: no receipt, and the permit-set equality check.
  - Finish (the §6.4 precedence table), Recover (the §6.5 table) and ReleaseReservation, all using the shared A→P→J'→K'→E close statements.
  - ReadinessProbe and ListExpiredLeases (one statement each), PublishPresence, and the harness-only SetQueueState.
  - Retry delays use the shared `RetryEvaluator` with `RandomNumberGenerator` entropy drawn once per deciding transaction.
- `PostgresServices.Store.cs` registers the data sources, runner and store. `IFaultInjector` defaults to the no-op injector.
- Harness pieces that these tests need (completed in SP-003):
  - `StoreServer` keeps the template `rw_template` and creates one database per test.
  - `DriverFixture`, `TestClient` (the real DI graph), `HarnessFaultInjector` (throw, delay, barrier, drop reply) and `SnapshotReader` (a REPEATABLE READ normalized snapshot plus the reference-model view).
