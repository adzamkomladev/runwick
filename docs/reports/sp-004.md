## Defects fixed

Serialization (`src/Runwick/Serialization/**`):

1. **Exactly-1 MiB payloads were rejected.** `BoundedBufferWriter` compared the writer's worst-case size hint against the limit. It now fails only when the bytes actually written exceed the limit. Over-limit buffering stays bounded at limit + 64 KiB.
2. **Lone surrogates were silently replaced with U+FFFD at Prepare.** Both encoders do this replacement. A strict validation pass now runs only when the output contains an escaped U+FFFD, and the payload is rejected with `payload_invalid_utf8`.
3. **Depth > 32 at Prepare returned `payload_invalid_value`.** STJ wraps the depth error in an inner exception; it now returns `payload_depth_exceeded`.
4. **A null for a non-nullable constructor member was reported as `payload_missing_required`.** It is now `payload_invalid_value`.
5. **Scanner and canonical-encoder messages echoed property names and number lexemes**, which spec 01 §14.1 forbids. They now report byte offsets.
6. **The canonical encoder emitted non-§11 codes.** An unused, divergent second JSON parser (`CanonicalValue.FromJson`) was also removed.
7. **Prepared-envelope import (`PreparedEnvelopeCodec`) had several gaps:**
   - It had no strict UTF-8, escape or duplicate-member parse. Invalid UTF-8 could escape as an `InvalidOperationException`.
   - The store/application check ran before the schema and payload checks, which is not the §9.3 order.
   - Large integers threw `OverflowException`.
   - A missing `eligibility.mode` threw `KeyNotFoundException`.
   - Metadata combined bounds, reserved business keys and trace formats were not checked.
   - Policy accepted 1–1,000 executions and unbounded delays. Import now enforces the I-23 bounds and the 10-year uniqueness window.

Dispatch (`src/Runwick/Dispatch/DispatchPreparer.cs`):

8. **Business metadata named `traceparent` or `tracestate` was accepted.** It is now rejected with `invalid_metadata`.

Registration (`src/Runwick/Registration/RegistryCompiler.cs`):

9. **Policy bounds did not match the storage contract.** MaxExecutions and MaxUnstartedAbandonments are now 1–100, ExecutionTimeout ≤ 30 days, and retry and unstarted-recovery delays ≤ 24 h.
10. **`JobDefaults` same-layer conflicts were reported once per job, or not at all when no job was registered.** They are now reported exactly once.
11. **The serializer-metadata walk had gaps:**
    - `[JsonConverter]` on types and properties was not rejected.
    - `JsonDerivedType` subtypes were not walked.
    - Arrays and `object` elements were caught only by accident.

## Spec changes

- Spec 01 I-23 records the 1–100 / 30-day / 24-hour bounds. The §5.4 validation-table rows (`WithMaxExecutions`, `WithExecutionTimeout`, `WithRetryDelay`, `WithMaxUnstartedAbandonments`, `WithUnstartedRecoveryDelay`) now state the upper bounds. Spec 01 had no literal "1–1,000" for these settings.
- Spec 02 IC-21: §11's `metadata_invalid` and `identity_invalid` contradict spec 01's `invalid_metadata` and `invalid_*` identity codes. The spec 01 names are kept.
- Spec 02 IC-22: import validates metadata with the Prepare rules and codes, as SER-03 requires ("identically").

## Notes and deviations

- **Test project setting.** `tests/Runwick.Core.Tests` sets `IsTestingPlatformApplication=false`, because the .NET 10 SDK refuses VSTest runs of an xunit v3 project otherwise. `tests/Runwick.Postgres.Tests` needs the same line, but that project was out of scope here.
- **Import code for an oversized envelope.** Prepare uses `envelope_too_large` or `batch_envelope_too_large`; import uses `prepared_envelope_too_large` (01 I-22). For a single dispatch, the 2 MiB envelope limit cannot be reached because the payload is capped at 1 MiB, so it is tested through a batch.
- **Contract tests left out.** SER-10 `CommandExpired`/`ResolveAsync` and the PostgreSQL half of SER-12 need a store, so they are not in this Pure suite.
- **Worker pool validation not implemented.** Pool and timing validation (`worker_without_pool`, lane weights and similar) is not implemented anywhere and was out of SP-004 scope. The pool builders (`src/Runwick/Registration/Builders.cs`) record settings, but nothing validates them; the code constants exist in `RunwickErrorCodes`.
- **Unused resolvers.** `AddJsonTypeInfoResolver` resolvers are stored but never consulted by the profile. This is left as is.
- **Node and C# disagree on `{"a":-}`.** Node reports `payload_invalid_json` and C# reports `payload_invalid_number`. No vector covers this input.
