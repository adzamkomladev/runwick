# PF-02: frame batching

Date: 2026-11-01. Host: the shared KVM guest (8 vCPU), **non-reference**. Store: `runwick-pg` (PostgreSQL 18) at 127.0.0.1:55499, through `docker-proxy`. Spec: 04 and 07 "Changes (2026-11-01, PF-02)".

## 1. What changed

- **Gate batch:** the session timeouts, G1 and G2 go out as one batch (one round trip instead of three).
- **Receipt batch:** R1, R3 and the receipt clock go out as one batch.
- **Staged paths:** the read-only check and `SAVEPOINT` are one command, so `StageAsync` and `StageFinishAsync` lose a round trip. On a read-only transaction the savepoint is released before the refusal.
- **Unchanged:**
  - lock order;
  - fresh time after the last lock;
  - the receipt replay branch;
  - `synchronous_commit`.

  The only fault point that moves is `BeforeGateLock` (07 note).
- **CAP-10 calibration (C-9):** the threshold is now `3 × p90(Renew round trip) < 350 ms`. The p90 is measured under the calm load and noted in 07.

## 3. Floor, interleaved A/B (A = PF-01, B = PF-02)

`floor --n 100 --warmup 10`, run in the order A1, B1, A2, B2 on `rw_pf_a005`. Each run's load average is noted below. The host was heavily loaded by other sessions, so the latencies are very noisy. Only the deterministic command counts are evidence.

| Run (load start → end) | Dispatch p50 | Reserve p50 | Begin p50 | Renew p50 | Finish p50 |
|---|---|---|---|---|---|
| A1 (14.1 → 13.0) | 116 | 113 | 131 | 100 | 182 |

Times are in ms. On B-minus-A pairs, Finish and Renew are consistently faster (−29 % and −20 to −32 %). Reserve and Begin are mixed: B1 was the run that took the load from 13 to 19.5. No latency target is checked on this host.
