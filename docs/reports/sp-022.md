# SP-022: telemetry

Date: 2026-11-08. Branch `worktree-agent-a4e9551ff5dbbba37`, from main `51a67ed`. Spec: docs/spec/18-telemetry.md (see its Changes list, 2026-11-08).

## What was built, in one paragraph

Runwick now reports what it is doing through the standard .NET tools. One trace source and one meter, both called `Runwick`, cover dispatch, workers, settlement, leases, recovery, scaling, schedules, management and retention. Logs have fixed event IDs, and noisy events are limited to 10 per minute with one summary line. Each role (producer, worker, scheduler, management) reports its own health. ASP.NET Core hosts get matching health checks. A new package, `Runwick.OpenTelemetry`, connects all of this to the OpenTelemetry SDK. Nothing is exported unless the host adds a listener or exporter. A Grafana dashboard and Prometheus alert rules ship in `ops/`.

## Main pieces

- **Core** (`src/Runwick/Telemetry/`): the source, the meter, 33 instruments, a per-instrument limit on distinct tag sets (default 1,000, plus one overflow series), log events, and the per-role health service.
- **Worker:** a root `process` span per attempt, linked to the dispatch trace. Child spans cover begin, execute, cleanup and settle. Gauges are rebuilt once a second, so metric callbacks never call the store.
- **Dispatch, scheduler, recovery, scaling, management:** spans and counters. Management calls are measured by a wrapper around the session.
- **Application collector:** samples queue backlog and schedule review numbers. It makes one bounded query per period, with a 1 s budget and at most 64 queues per sample. The Postgres query is in `PgStore.Telemetry.cs`.
- **Health:** `IRunwickHealth` reports liveness plus readiness per role. `AddHealthChecks().AddRunwick()` maps that into ASP.NET Core checks.
- **`Runwick.OpenTelemetry`:** `AddRunwickInstrumentation()` for traces and metrics. It adds one view per instrument that keeps only the spec's tags and caps the series count, so the SDK's own overflow never fires.
- **Ops files:** `ops/grafana/runwick-overview.json` and `ops/prometheus/runwick-alerts.yml`.

## Deviations from the spec (all recorded in its Changes list)

- **Listener exceptions are caught** at the instrument and span call. The spec said they would pass through. In OBS-01 (c) a throwing listener reached the Begin, Finish and drain paths, so catching was needed to keep ownership safe. Failures are counted and logged once at Debug.
- **`execution.authorized` counts once per attempt**, even when the Begin reply was replayed in the same process. Before this change, a dropped first reply led to a count of 0.
- **`RunwickStoreIncompatible` alert** reads a gauge the host provides (`runwick_host_readiness_incompatible`), because health is not a Runwick metric. **`RunwickFailuresRepeated`** groups by queue and job, because `error.type` is not a metric tag.
- **New option `CollectorName`** (default `default`) supplies the `runwick.collector` tag value.
- **The worker's free-text diagnostics are logged at Debug**, and the scope-disposal diagnostic gives the exception type, not its message (redaction). `WorkerEngineTests.Scope_cleanup_failure_after_timely_success_keeps_success` and Postgres `WorkerTests.Cleanup_failure_after_timely_success_is_recorded_as_success` were updated to check for the type.

## Gaps

- **OBS-08** (kill a peer process after Finish, then restart and replay) and **OBS-11** (overhead under load) were not run.
- **OBS-10:** SP-021 must call `Telemetry.RetentionBatch`, `Telemetry.RetentionCaughtUpAt` and `RunwickLog.RetentionBatchFailed`, and add the `runwick.retention.batch` span. The instruments already exist.
- **Some log events are defined in the spec but not emitted yet:** 1006, 1009, 1010, 1014, 1201–1203, 1301–1302, 1402–1405, 1502–1503, 1702 and 1703.
- **Not recorded yet:** `runwick.storage.operation.duration` exists but has no measurements. The `stage {queue}` span (transactional staging) is not built.
- **Gauges are not limited by the series cap.** Their tag sets come from configuration (pools, queues), so they are already bounded.
- **Health refresher:** it adds one `DescribeAsync` call every 10 s per host. Tests that count store round trips over long fake-time runs may see these calls.
- **Pre-existing on main, not caused by this change:** `PackageGraphTests` fail because `Runwick.Dashboard.Spike` is not declared in `eng/package-graph.json`.
- **Not linted:** `promtool` is not installed, so the alert rules were checked only by `OpsAssetTests`.
- **Harness change:** `StoreServer` now reads `RUNWICK_TEST_TEMPLATE`. The line is identical to the one on the SP-032 branch.
