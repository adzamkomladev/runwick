# SP-024 report: the Runwick dashboard

Date: 2026-11-08. Spec: [21-dashboard.md](../spec/21-dashboard.md). Built on the SP-023 spike (Inertia.Net 1.7.0, named mounts).

## What was built

- **`src/Runwick.Dashboard`**: the package. `AddRunwickDashboard(id, ...)` registers a named Inertia mount; `MapRunwickDashboard(path)` mounts it. Pages: Jobs, Job, Queues, Workers, Schedules, Scaling, Settings, Retention, Audit. Every read and control goes through the management session, so permissions, limits and audit rows are the same as the JSON API.
- **The client** (`ClientApp/`, React 19 + Inertia 3.9.1, built with Vite 8.3.4). The built files are committed in `dist/` and embedded as resources. `dist/source.sha256` is a hash of every client source file; a test recomputes it, so a source change without a rebuild fails (DSH-01). The package ships `dist` only, no `ClientApp/` or `node_modules` (DSH-04).
- **New management read `ListScalingEvents`**: interface, session, metered wrapper, JSON route `GET scaling-events`, PostgreSQL. SQLite has it in `src/Runwick.Sqlite/Store/SqliteStore.ScalingEventsRead.cs`; that file does not declare the management interface (it lands with the SQLite management part), so the SQLite method has no test yet.
- **`eng/package-graph.json`**: `Runwick.Dashboard` is built and may reference only `Runwick.AspNetCore` and the package `Inertia.Net`. `eng/check-package-graph.sh` passes.
- **`samples/Runwick.Dashboard.Host`** replaces the spike host: a host with its own Inertia page at `/ops/`, the dashboard at `/ops/runwick`, PostgreSQL, seeded jobs including hostile text.
- **Removed**: `src/Runwick.Dashboard.Spike`, `tests/Runwick.Dashboard.Spike.Tests`, `samples/Runwick.Dashboard.SpikeHost`.

## Deviations and things found while running

- **WebKit not run**: this machine lacks the Playwright WebKit system libraries ("Host system is missing dependencies"). DASH-07's WebKit smoke result is still owed from a machine that has them.
- The sample host and the Chromium flows had never been run against the ported UI. Fixes to get them green: the sample's login redirect dropped the `/ops` prefix; the sample's staff now get `Jobs.ReadPayload`, `Jobs.ReadError` and `Audit.Read` explicitly (the presets leave them out by design, 16 section 1); the flow looked for audit operation `RetryJob` but the audit text is `ManualRetry`; the seed now dispatches the hostile-payload job last so it lists first (reveals are rate limited).
- **One real client fix**: a revealed payload stayed on screen after a command's 303 on the same page. The reveal value is now also cleared on Inertia's `success` event (spec 21 section 6: cleared on navigation). The client was rebuilt and `source.sha256` updated.
- `browser.sh` waits up to two minutes for the host to start (the machine was heavily loaded by parallel agents).

## Update 2026-11-09: client rebuilt on shadcn/ui

The person who runs the dashboard asked for shadcn/ui components and micro-interactions. What changed:

- **Look and layout.** Every page now uses shadcn/ui components (Radix primitives, Tailwind CSS compiled into the one static stylesheet). There is a sidebar, which becomes a slide-out panel on phones. Tables sort by column on the page you see and have filter toolbars. Job, queue and schedule states are badges. Confirmations open a dialog, and command results appear as toasts. Answers that need a next step stay on the page: "Check again", "Try again" and bulk results. A skeleton shows while a page loads. There are light, dark and system themes.
- **Micro-interactions.** Buttons respond to hover and press, and show a spinner while their command is sent. Polled numbers count up to their new value. A row flashes when its state changes, and pages fade in. Copy buttons turn into a check mark. A pulsing "Live" badge turns to "Paused" when the tab is hidden. Everything is cut to no motion under `prefers-reduced-motion`.
- **New Overview page** (`/overview`, spec 21 section 4). It has five key-figure cards with small trend lines (jobs created in the last hour, failures in the last 24 h, pending jobs, live workers, scaling target), plus recent failures, queues and the latest scaling events. It uses only existing reads. Each figure counts the rows of one read's first page and shows "50+" beyond that, so it is never a total. The mount root is still the Jobs page.
- **Choices forced by the rules:**
  - **Icons:** Tabler icons (MIT) instead of lucide (ISC).
  - **Charts:** hand-drawn SVG trend lines instead of Recharts, whose d3 packages are ISC.
  - **Local shims:** two replace `react-remove-scroll` and `aria-hidden`. The real ones inject a `<style>` tag, which the CSP blocks, and pull in `tslib`, which is 0BSD.
  - **Allow-list:** `npm:Apache-2.0` is added, for `class-variance-authority`.

  If the owner allows ISC, lucide and Recharts can replace the icons and trend lines.
