## Spec changes (dated 2026-10-31)

10 is a new document; it replaces 03 §6.3. Contradictions resolved (10 "Changes"): the edit freeze is normative (C-1); Begin stays `Begin/1`, guarded by the `rate_admission` capability on every creation path (C-2); seeds travel with the dispatch item (C-3). Implementation choices: the builder surface (no queue-rate builder in M3), a separate `EditRatePolicy/1`, and deferral jitter stored in the receipt.

## Fixes found while testing

- CMD-06 (test only): the test compared two deferral records with record equality, and the records contain lists, which compare by reference. It now compares the deferral fields and `BlockingScopes` element by element.
- RATE-03 (test only): on a loaded host the retry's Begin could arrive after the first grant's window had already passed, and then the retry is correctly Applied. The assertion now depends on timing: if `DecidedAt ≥ firstGrant + Window`, it expects Applied with four grants; otherwise it expects a deferral.

- Owed cases (2026-11-01): no product defect found; no product code changed. Test-side fixes while writing them: PGX-01 checked `store_metadata.revision` instead of `schema_revision`, and published presence with a status the check constraint does not allow (`running` → `ready`). RATE-10: libfaketime applies a clock step to running backends at different moments, and a statement caught across a 60 s step tripped the session's idle-in-transaction timeout (a not-applied reply). The step is now 30 s, as in TIME-13, and Reserve/Begin retry a not-applied reply (Begin with the same command ID and NotAfter).
